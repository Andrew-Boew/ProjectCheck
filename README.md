# ProjectCheck

ProjectCheck — консольная утилита для проверки локального проекта перед публикацией. Она показывает замечания, но не изменяет проверяемые файлы.

## Требования и запуск

- Python 3.11 или новее. Сторонние Python-пакеты не нужны.
- Git нужен для учёта `.gitignore`. Без Git утилита обходит файлы напрямую.

```bash
python3 projectcheck.py /путь/к/проекту
python3 projectcheck.py /путь/к/проекту --format json
python3 projectcheck.py /путь/к/проекту --fail-on-findings
```

Если переданная папка является корнем Git-репозитория, проверяются отслеживаемые и новые неигнорируемые файлы. Файл, уже добавленный в Git, проверяется даже при наличии правила для него в `.gitignore`. Для обычной папки выполняется прямой обход. Каталоги `.git`, `.venv`, `venv`, `node_modules`, `__pycache__` и символические ссылки пропускаются.

## Проверки

| Код | Что проверяется |
| --- | --- |
| `README` | Наличие `README.md`, `README.rst` или `README.txt` в корне |
| `GITIGNORE` | Наличие `.gitignore` в корне |
| `TESTS` | Наличие Python-файла `test_*.py` или `*_test.py` |
| `SENSITIVE` | Имена `.env`, `.env.*`, `id_rsa`, `id_ed25519`, `id_ecdsa`, `id_dsa` и расширения `.key`, `.p12`, `.pfx` |
| `HARDCODED_SECRET` | Непустые строковые значения секретных полей в Python, JSON, TOML и YAML-конфигурациях, а также заполненные секретные переменные в `.env` |
| `TEMP` | Расширения `.tmp`, `.bak`, `.swp`, `.swo`, имена с `~` на конце и `.DS_Store` |
| `LARGE` | Файлы больше заданного порога, по умолчанию 10 МиБ |
| `SCAN_ERROR` | Ошибка чтения папки или получения размера файла |

Для `.env.example`, `.env.sample` и `.env.template` предупреждение `SENSITIVE` не создаётся, и их содержимое не проверяется. Проверка `HARDCODED_SECRET` разбирает `settings.py`, `config.py`, `settings.json`, `config.json`, `appsettings.json`, `settings.toml`, `config.toml`, `pyproject.toml`, проверяемые `.env`-файлы, а также YAML-файлы с именами `settings`, `config`, `application`, `compose`, `docker-compose` или `values` и расширением `.yml`/`.yaml`. Значение секрета в отчёт не выводится. Пустые значения и ссылки вида `${VAR}`, а также присваивание через `os.getenv()` в Python не считаются захардкоженным значением. Для JSON/TOML номер строки пока не определяется. YAML проверяется по простым строковым шаблонам, без полного разбора синтаксиса; возможны пропуски и ложные срабатывания. Проверка `TESTS` пока распознаёт только Python-тесты.

## Настройки

В корне проверяемого проекта можно создать `.projectcheck.toml`:

```toml
max_size_mib = 20
exclude = ["generated/", "*.bak"]
```

`max_size_mib` — положительное целое число. `exclude` — список путей и шаблонов относительно корня проекта. Запись `generated/` исключает папку целиком, `*.bak` — подходящие файлы.

Параметры можно задать и при запуске:

```bash
python3 projectcheck.py . --max-size-mib 5 --exclude 'generated/' --exclude '*.bak'
```

Порог из командной строки заменяет значение из TOML. Исключения из командной строки добавляются к исключениям из TOML.

## Отчёт и код завершения

Текстовый отчёт выводится по умолчанию. `--format json` выводит объект с полями `project`, `count` и `findings`. Каждое замечание содержит `code`, `message`, `path`, `line` и `confidence`. Для проверок проекта в целом `path` и `line` равны `null`. Уверенность (`high`, `medium`, `low`) показывает надёжность срабатывания правила, а не важность проблемы. Строка отображается и в текстовом отчёте как `путь:номер`.

| Код завершения | Значение |
| --- | --- |
| `0` | Проверка завершилась; замечания допускаются без `--fail-on-findings` |
| `1` | Есть замечания и указан `--fail-on-findings` |
| `2` | Ошибка аргументов, конфигурации или неполная проверка (`SCAN_ERROR`) |
